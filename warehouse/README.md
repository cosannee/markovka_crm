# Склад — этап 1, локальная версия на проверку

Рабочая база не изменена. Миграция не применена. Изменения не опубликованы.
База исходного кода: main 7ce2e95d689204e665983004c922e8d96e3eabb9.

## Подготовлено
- Раздел «Склад» в «Ещё», отдельные JS/CSS; существующая палитра не меняется.
- Каталог, новые категории, поиск, редактирование/архив, фото в отдельном приватном Storage bucket.
- Массовые назначения мастерам, выбор всех материалов, отдельные минимумы.
- Собственный склад для master/director, управление всем складом только manager.
- Неизвестный остаток ≠ ноль. Количества до трёх знаков; штуки/упаковки целые.
- Полная инвентаризация со снимком назначений, сохранение частями, подтверждение неизменившихся количеств, история и причина исправлений.
- Проверки раз в 14 дней, индивидуальная настройка. Частичная проверка не переносит срок полной.
- Атомарный серверный запрос, версии записей, уникальный запрос для повторов. Неподтверждённый запрос сохраняется в IndexedDB отдельно от очереди заказов. При сбое записи на устройстве команда не отправляется.
- Смена единиц после появления количества или нормы блокируется. Архивирование сохраняет историю.

## Что проверить перед применением
1. Проверка `000-preflight-READ-ONLY.sql` выполнена пользователем. Сверить роли и поля crm_profiles, auth.uid, storage, существующие policies и отсутствие конфликтующих имён. Получен пользовательский результат проверки рабочей схемы: см. COMPATIBILITY.md.
2. Проверить активные профили: Александра — manager; Даша — director. Не менять роли ради склада.
3. Развернуть `001-warehouse.DRAFT.sql` сначала в отдельной тестовой Supabase. Файл намеренно вне папки автоматических миграций, не предназначен для повторного запуска.
4. Проверить реальные сессии manager/master/director, загрузку/просмотр фото, истечение авторизации, переходы разделов, iPhone Safari/PWA с клавиатурой и нижним меню. Локальные тесты используют изолированный PostgreSQL и браузер с тестовыми ответами; они не заменяют проверки реальной инфраструктуры.
5. После отдельного согласования применить проверенный SQL к production, затем публиковать index.html и папку warehouse (только JS/CSS нужны на сайте). До согласования не push/не deploy.
6. Создать категории/материалы, выбрать реальные единицы и назначения. Не выдумывать начальные остатки, минимумы или единицы палитры. Автозаполнения Н1–Н16 нет: существующая палитра доступна как справочник.

## Безопасное внедрение / откат
Миграция в транзакции: ошибка откатывает её целиком. Не удаляет/не меняет orders/tasks/finance и существующие RPC. Новые таблицы в закрытой схеме crm_stock, RLS включён, браузеру доступ только через три проверяющие права функции.
При проблеме после запуска откатить интерфейс до предыдущей версии. Не удалять складские таблицы, историю или приватные фото. При необходимости отдельно отозвать EXECUTE складских RPC; остальные разделы сохраняют свои права.
Не предоставлять директору складские права администратора автоматически.

## Локальные проверки
`tests/warehouse.mjs` — PGlite (PostgreSQL), синтетические роли/данные: права, дедупликация, неизвестный/нулевой остаток, идемпотентность, частичность, конкурентные изменения, транзакционный откат, валидация, история, единицы, отсутствие изменений в заказах.
`tests/warehouse-ui.mjs` — отдельный headless Chrome: форма материала, ширина 430×932, явные проверки, частичное сохранение, обрыв сети и повтор после перезагрузки через IndexedDB, ограничения мастерского интерфейса.
Для воспроизведения: Node 24+, @electric-sql/pglite 0.5.16, playwright-core 1.56.1; пути модулей можно передать через PGLITE_MODULE и PLAYWRIGHT_MODULE, Chrome — CHROME_PATH. Тесты не обращаются к production.

## Ограничения текущей версии
- Серверные проверки на реальном Supabase выполнены: LIVE-VERIFICATION.md. Ручная проверка Safari/PWA ещё не выполнена; публикация требует отдельного подтверждения.
- Записи склада сериализуются отдельным коротким advisory lock (не связан с заказами/финансами). При росте частоты записей можно разделить блокировки по складам с отдельным протоколом каталога.
- История отдаётся страницами по 100. Справочники/остатки загружаются при открытии склада, не при старте CRM.
- Список сессий пока полный; при росте архивов потребуется пагинация сессий.
- Неуспешно прикреплённые фотографии могут остаться в приватном bucket; автоматическое удаление не выполняется, чтобы не затронуть используемые файлы.
- Никаких закупок, движений, автосписаний или финансовых операций в этом этапе нет.
